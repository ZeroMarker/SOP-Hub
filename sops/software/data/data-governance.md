## 1. 目的

规范数据采集、存储、加工、使用、共享和销毁流程，提升数据质量、数据安全和数据可用性，支撑业务分析、产品决策和合规管理。

## 2. 适用范围

适用于公司业务数据、用户行为数据、日志数据、指标数据、报表数据、数据仓库和数据服务接口的治理活动。

## 3. 术语与定义

| 术语 | 定义 |
|------|------|
| 数据资产 | 具有业务价值并被统一管理的数据集合 |
| 数据标准 | 对数据口径、命名、格式、类型和使用规则的统一约定 |
| 数据血缘 | 数据从来源到加工、使用和输出的流转关系 |
| 数据质量 | 数据在准确性、完整性、一致性、及时性和唯一性方面的表现 |
| 指标口径 | 指标计算逻辑、统计周期、过滤条件和适用范围 |
| 数据脱敏 | 对敏感数据进行隐藏、替换或泛化处理 |

## 4. 职责分工

### 4.1 数据负责人
- 制定数据治理策略、标准和优先级
- 协调跨团队数据问题
- 审批核心数据资产和指标口径

### 4.2 数据工程师
- 建设数据采集、清洗、加工和调度流程
- 维护数据仓库、数据集市和数据服务
- 处理数据质量和数据链路异常

### 4.3 数据分析师
- 定义业务指标和分析口径
- 输出报表、看板和分析结论
- 反馈数据质量问题和口径差异

### 4.4 产品/业务负责人
- 明确业务含义和使用场景
- 确认指标口径和业务规则
- 验收数据产品和分析结果

### 4.5 安全负责人
- 制定数据分级分类和访问控制要求
- 审批敏感数据使用和对外共享
- 监督数据安全和合规执行

## 5. 操作流程

### 5.1 数据需求流程

```
需求提出 → 场景确认 → 数据源评估 → 口径定义
→ 排期开发 → 验收上线
```

**需求登记要求：**

- 使用场景和业务目标
- 数据范围、时间周期和更新频率
- 期望输出形式：报表、看板、接口、数据集
- 口径负责人和验收人
- 安全等级和权限范围

### 5.2 数据标准管理流程

```
标准制定 → 评审确认 → 发布执行 → 差异整改 → 定期复审
```

**标准内容：**

- 表、字段、指标和标签命名规范
- 数据类型、单位、枚举值和时间格式
- 维度、指标和业务口径定义
- 数据分级分类和保留周期

### 5.3 数据开发流程

```
数据源接入 → 建模设计 → 数据加工 → 质量校验
→ 任务调度 → 结果验收 → 文档登记
```

**开发要求：**

1. 数据模型需经过评审后开发
2. 核心任务必须配置调度监控和失败告警
3. 指标计算逻辑必须写入数据字典
4. 数据加工脚本纳入版本管理
5. 生产变更需按发布流程执行

### 5.4 数据质量管理流程

```
规则配置 → 自动校验 → 异常告警 → 问题定位
→ 修复处理 → 复盘改进
```

**质量规则：**

- 完整性：关键字段非空
- 准确性：取值范围和计算逻辑正确
- 一致性：同一指标不同报表口径一致
- 及时性：数据按约定时间产出
- 唯一性：主键、订单号等关键字段不重复

### 5.5 数据权限流程

```
权限申请 → 业务审批 → 安全审批 → 权限开通
→ 使用审计 → 到期回收
```

**权限要求：**

- 按岗位和使用场景授予最小权限
- 敏感数据访问需单独审批
- 临时权限必须设置到期时间
- 定期审计高权限账号和导出记录

## 6. 特殊情况处理

### 6.1 数据异常
- 立即标记受影响报表、接口或任务
- 通知使用方暂停引用异常数据
- 定位数据源、加工逻辑或调度问题
- 修复后进行补数和结果复核

### 6.2 指标口径冲突
- 收集冲突报表和计算逻辑
- 由业务负责人和数据负责人共同确认标准口径
- 更新数据字典和历史报表说明

### 6.3 敏感数据导出
- 明确导出目的、范围、接收人和保留周期
- 完成业务和安全审批
- 文件加密传输并记录审计日志
- 到期确认删除或归档

## 7. 服务质量要求

| 项目 | 标准 |
|------|------|
| 核心指标口径登记率 | 100% |
| 核心数据任务成功率 | ≥ 99% |
| 数据质量规则覆盖率 | 核心表 100% |
| 数据异常响应时间 | ≤ 30 分钟 |
| 权限审批记录完整率 | 100% |
| 敏感数据脱敏率 | 100% |

## 8. 信息安全管理

- 数据按公开、内部、敏感、机密进行分级分类
- 敏感数据默认脱敏展示和最小化采集
- 数据导出、共享和删除必须留痕
- 生产数据不得未经审批复制到个人设备
- 数据保留和销毁按合规要求执行
