## 1. 目的

规范软件应用安全管理过程，将安全要求融入需求、设计、开发、测试、发布和运维全生命周期，降低漏洞、数据泄露和权限滥用风险。

## 2. 适用范围

适用于公司 Web 应用、移动应用、后端服务、API、数据平台、内部系统和第三方集成系统的安全管理。

## 3. 术语与定义

| 术语 | 定义 |
|------|------|
| SAST | 静态应用安全测试，通过分析源代码发现安全缺陷 |
| DAST | 动态应用安全测试，通过运行环境扫描发现安全问题 |
| SCA | 软件成分分析，用于识别开源组件漏洞和许可证风险 |
| 威胁建模 | 识别系统资产、攻击面、威胁和缓解措施的分析过程 |
| 最小权限 | 仅授予完成工作所需的最低权限 |
| 安全基线 | 系统和应用必须满足的最低安全配置要求 |

## 4. 职责分工

### 4.1 安全负责人
- 制定应用安全策略、安全基线和检查标准
- 组织安全评审、漏洞管理和安全事件响应
- 推动安全培训和安全能力建设

### 4.2 安全工程师
- 执行威胁建模、代码扫描、漏洞扫描和安全测试
- 跟踪漏洞修复和复测
- 提供安全设计和修复建议

### 4.3 开发工程师
- 按安全编码规范开发
- 修复安全缺陷和依赖漏洞
- 配合安全评审和应急响应

### 4.4 测试工程师
- 将安全用例纳入测试范围
- 验证认证、授权、输入校验和敏感数据保护
- 记录并跟踪安全缺陷

### 4.5 运维工程师
- 落实应用部署安全基线
- 管理证书、密钥、访问控制和安全监控
- 配合安全事件隔离和恢复

## 5. 操作流程

### 5.1 安全需求流程

```
需求识别 → 安全分级 → 安全要求定义 → 安全评审 → 需求确认
```

**安全需求范围：**

- 认证登录、权限控制和会话管理
- 敏感数据采集、传输、存储和销毁
- 支付、资金、订单等高风险业务
- 文件上传、导出、分享和外部接口
- 审计日志、风控策略和合规要求

### 5.2 安全设计流程

```
资产识别 → 攻击面分析 → 威胁建模 → 安全方案设计
→ 安全评审 → 风险登记
```

**设计要求：**

1. 明确用户角色、权限模型和数据边界
2. 对外部接口进行鉴权、限流和签名校验
3. 敏感数据传输使用 HTTPS/TLS
4. 密码、密钥和令牌不得明文存储
5. 关键操作必须记录审计日志

### 5.3 安全开发流程

```
安全编码 → 依赖检查 → 密钥检查 → 代码评审
→ 静态扫描 → 缺陷修复
```

**开发要求：**

- 输入参数必须进行校验和过滤
- SQL 操作使用参数化查询
- 文件上传限制类型、大小和存储路径
- 错误信息不得暴露堆栈、路径或敏感配置
- 禁止将账号、密码、Token、API Key 提交至代码库

### 5.4 安全测试流程

```
测试计划 → SAST/SCA 扫描 → DAST 扫描 → 手工验证
→ 漏洞确认 → 修复复测 → 安全报告
```

**测试范围：**

- 认证绕过、越权访问、会话固定
- 注入、跨站脚本、跨站请求伪造
- 敏感数据泄露、弱加密、弱口令
- 文件上传、下载和路径穿越
- 接口重放、频率限制和业务风控

### 5.5 漏洞管理流程

```
漏洞发现 → 漏洞确认 → 风险评级 → 修复分派
→ 修复验证 → 漏洞关闭 → 趋势分析
```

| 级别 | 定义 | 修复时限 |
|------|------|----------|
| 严重 | 可导致系统被控制、大规模数据泄露或资金损失 | 24 小时内 |
| 高危 | 可导致敏感数据泄露、权限提升或核心业务风险 | 72 小时内 |
| 中危 | 存在可利用风险但影响范围有限 | 7 个工作日内 |
| 低危 | 安全加固或配置优化类问题 | 30 个自然日内 |

## 6. 特殊情况处理

### 6.1 安全事件
- 立即隔离受影响系统或账号
- 保留日志、样本和现场证据
- 通知安全负责人和业务负责人
- 完成根因分析、修复、复盘和通报

### 6.2 第三方组件高危漏洞
- 立即确认受影响系统和版本
- 优先升级、替换或临时缓解
- 对无法立即修复的组件设置风险豁免和到期时间

### 6.3 紧急上线
- 完成最低安全检查，包括密钥、权限、输入校验和依赖漏洞
- 记录未完成安全项和补齐时间
- 上线后补做完整安全测试

## 8. 信息安全管理

- 所有生产密钥由密钥管理系统托管
- 安全测试数据必须脱敏
- 安全报告按敏感资料管理，限制访问范围
- 离职和转岗人员权限需及时回收
